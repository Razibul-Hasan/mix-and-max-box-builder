# Building it in WordPress

How this system maps onto the plugin. Built with `@wordpress/scripts`, React through `@wordpress/element`, WooCommerce 8+.

## Names and prefixes

| Thing | Name |
| --- | --- |
| Plugin slug and text domain | `mix-and-max-box-builder` |
| PHP functions, options, hooks, meta keys | `mmbb_` (classes under a `MixMax\BoxBuilder` namespace) |
| CSS classes | `mmbb-` |
| REST namespace | `mmbb/v1` |
| Block | `mmbb/box-builder` |
| Shortcode | `[mmbb_box id="…"]` |
| JS global (this bundle) | `window.MixMax` |

## Admin

- Top-level menu "Mix and Max" (capability `manage_woocommerce`) with submenus Dashboard, Campaigns, Analytics, Settings. Each renders `<div id="mmbb-admin" class="mmbb-root" data-page="…">`; the React app mounts there and draws `AdminShell`.
- On those screens only, enqueue the admin bundle with the dependencies from `build/admin.asset.php` (`react`, `wp-element`, `wp-api-fetch`, `wp-i18n`), and call `wp_set_script_translations()`.
- Cancel `#wpcontent` left padding on the plugin screens so the shell runs full-bleed; hide unrelated admin notices inside the app area and show your own with `Notice`.
- All data through REST with `apiFetch` (nonce handled by core).

## Data

- Campaigns: a private custom post type `mmbb_campaign` (no public UI). Settings in post meta `_mmbb_config` (type, capacity, minimum, tiers, products, design, schedule) stored as validated JSON.
- Settings: one option `mmbb_settings` via `register_setting()` with a sanitize callback.
- Analytics: a custom table `{prefix}mmbb_events` (campaign, anonymous session hash, event, product, qty, time) for `view`, `add_item`, `tier_reached`, `add_to_cart`; revenue comes from WooCommerce orders that carry box meta. Roll up daily with Action Scheduler. Add a privacy-policy note with `wp_add_privacy_policy_content()`.

## REST routes (`mmbb/v1`)

| Route | Use | Permission |
| --- | --- | --- |
| `GET/POST /campaigns`, `GET/PUT/DELETE /campaigns/{id}`, `POST /campaigns/bulk` | Campaigns page and editor | `manage_woocommerce` |
| `GET /products?search=` | Product picker | `manage_woocommerce` |
| `GET /stats`, `GET /analytics` | Dashboard, Analytics | `manage_woocommerce` |
| `GET/POST /settings`, `GET /setup` | Settings, checklist | `manage_woocommerce` |
| `POST /events` | Storefront tracking | public, nonce, rate-limited |
| `POST /cart/box` | Add a box to the cart | public, nonce |

Every route has a `permission_callback` and sanitises its arguments; every output is escaped.

## Storefront

- The block's PHP render (and the shortcode) prints `<div class="mmbb-root mmbb-builder" data-campaign="12">` plus the campaign's public config (products, prices, stock, tiers) as escaped JSON, and enqueues the storefront bundle and styles only then.
- The storefront app composes `ProductTile`, `BoxSlots`, `TierProgress`, `BoxPanel` / `BoxSummaryBar`, `BoxSizePicker`, `Countdown`.
- Tokens are scoped to `.mmbb-root` so the builder never restyles the theme; the Dark theme applies when the merchant picks it in Design or Settings.

## Cart, pricing, orders

- `POST /cart/box` re-validates the box against the campaign rules and stock, calls `wc_load_cart()`, then `WC()->cart->add_to_cart()` with the box contents in cart item data.
- Bundled line: one cart line whose price is set in `woocommerce_before_calculate_totals` (item prices summed, tier discount applied server-side). Box-plus-items mode: each item is its own line linked to a parent box key.
- Contents shown in the cart and checkout with `woocommerce_get_item_data`; saved to the order with `woocommerce_checkout_create_order_line_item`; per-item stock reduced once the order's stock is reduced (`woocommerce_reduce_order_stock`), guarded by an order meta flag.
- Coupons don't stack on box discounts unless the setting allows it.
- Declare compatibility with HPOS (`custom_order_tables`) and the Cart & Checkout blocks (`cart_checkout_blocks`) on `before_woocommerce_init`.

## WordPress.org checklist

- GPLv2 or later; bundled fonts are SIL OFL; no CDN, font or tracking requests to third parties.
- Prefix everything; load nothing outside plugin screens and builder pages.
- Nonces plus capability checks on every write; sanitise in, escape out.
- `uninstall.php` deletes data only when the merchant opted in.
- Run Plugin Check before every release.
